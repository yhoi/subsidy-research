# 補助金・助成金 日次リフレッシュ（GitHub Actions 毎日 6:30 JST 自動実行用）

このプロンプトは `claude -p` から非対話で呼ばれます。最終出力は実行サマリー数行のみ。

**週次の本調査（`weekly-research-prompt.md`）とは役割が違います。**

| | 日次リフレッシュ（このプロンプト） | 週次の本調査 |
|---|---|---|
| 目的 | 既存案件の情報を最新に保つ | 新しい案件を見つけて棚卸しする |
| 新規案件の探索 | **しない** | する |
| `reports/YYYY-MM-DD.md` | **作らない** | 作る |
| Discord通知 | **飛ばない**（通知は `.md` の更新で発火するため） | 飛ぶ |
| 更新するファイル | `reports/latest.json` のみ | `latest.json` と `.md` |

## 役割

`reports/latest.json` に載っている**既存案件の状態だけ**を確認し、変化があれば更新する。締切間近の案件を見落とさないための日々の追従が目的であり、新しい案件を探すのは週次の仕事なのでここではやらない。

## 手順

### Step 1. 読み込み

`reports/latest.json` を読む。壊れている・読めない場合は `logs/errors.log` に追記して終了する（**勝手に作り直さない**）。

### Step 2. 確認対象の絞り込み

全件を毎日調べる必要はない。以下に該当するものだけをWebSearch/WebFetchで確認する。

- `deadline` が**30日以内**のもの
- `status` が「公募開始待ち」「結果発表待ち」「未定」系のWatch案件
- `deadline_note` に「要確認」「未掲載」「未公表」等の宿題が書かれているもの

該当が多い場合でも**検索は合計8クエリ程度まで**に抑える。取りこぼしは翌日と週次で拾えばよい。

### Step 3. 更新

確認できた変化を `latest.json` に反映する。

- 締切の確定・変更 → `deadline` と `deadline_note`
- 公募開始・受付終了・採択発表 → `status`
- 締切超過が確実なものは `subsidies` から削除する
- **`new_this_survey` は触らない。**新規判定は週次の担当なので、日次では付けalso外しもしない
- **新しい案件を見つけても追加しない。**気づいたものは `notes` に「週次で要確認: ○○」と1行だけ残す

`survey_date` は今日のJST日付に更新する。**スキーマの正は `docs/latest-json.md`。項目名を変えない**（`scripts/notify_discord.py` が読むため）。

### Step 4. コミット

**変化がなければ何もコミットせずに終了する。**空コミットを毎日積まないこと。

変化があった場合のみ:

```sh
git add reports/latest.json && git commit -m "chore: YYYY-MM-DD 日次リフレッシュ（N件更新）" && git push
```

`reports/*.md` は**絶対に作らない・触らない**。触るとDiscord通知が飛んでしまう。

## 出力

標準出力は実行サマリー数行のみ。例:

```
日次リフレッシュ完了（2026-08-27）
- 確認 4件 / 更新 1件 / 削除 0件
- 更新: ふくしま産業応援ファンド → 事前相談期間が 08-28 で終了と確認
- push あり
```

## 注意

- TodoWrite / TaskCreate は使わない（出力ノイズになる）
- 編集してよいのは `reports/latest.json` と `logs/` のみ
- 絵文字は使わない（このリポジトリは公開されている）
- 迷ったら「何もしない」を選ぶ。日次は保守的でよく、判断が要るものは週次に回す

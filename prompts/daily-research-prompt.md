# 補助金・助成金 週次調査 (launchd 毎週月曜 6:30 JST 自動実行用)

このプロンプトは `claude -p` から非対話で呼ばれます。沈黙で完了する想定で、最終出力は実行サマリー数行のみ。成果物は (1) `reports/YYYY-MM-DD.md`、(2) `reports/latest.json` の更新、(3) GitHubへのpush。

**Discordへの直接投稿はしない。** push を GitHub Actions（`.github/workflows/discord-notify.yml`）が検知して Discord に通知する設計。

## 役割

毎週月曜 6:30 JST にトリガされ、**会津大学発ベンチャー／会津・福島拠点のテック系スタートアップ**が申請可能な補助金・助成金・支援制度をWebで調査し、前回結果との差分をレポートする。

想定する申請主体の属性:

- 会津大学発ベンチャー（大学発ベンチャー認定・産学連携の枠を使える）
- 福島県会津若松市に拠点を置く中小企業・スタートアップ
- AI / ブロックチェーン / データ・DeepTech 領域の研究開発型

## 調査の重点

1. **会津地域**: 会津若松市・会津大学・AiCT（会津産業ネットワークフォーラム等含む）の独自制度、大学発ベンチャー支援
2. **福島県**: 県の産業振興・イノベーション系（福島イノベーション・コースト構想、産業振興センター、ハイテクプラザ等）
3. **DeepTech / 研究開発**: NEDO、JST（START/SBIR等）、AMED以外の技術系、大学発ベンチャー支援、ディープテック・スタートアップ向け大型支援
4. **東北**: 東北経済産業局、東北のVC/自治体連携プログラム
5. **全国（中小企業一般）**: 経産省・中小企業庁・IPA・IT導入補助金・ものづくり補助金・持続化補助金・新事業進出/事業再構築系

拾う基準: 上記属性の法人が**申請主体になれる**もの。大学研究者個人のみが対象の科研費型、個人向け給付は捨てる。判断に迷うものは関連度「低」で掲載してよい。

## リポジトリ構成の前提

| パス | 役割 |
|------|------|
| `reports/latest.json` | 最新の調査結果。**前回状態の正であり、差分検知の基準** |
| `reports/YYYY-MM-DD.md` | 調査レポート（このプロンプトが毎回作る） |
| `.github/workflows/discord-notify.yml` | push検知でDiscord通知。`latest.json` を読むので**スキーマを壊さない** |

## 手順

### Step 1. 日付の確定と重複防止

`date` で今日のJST日付を取得 → `today`。`reports/<today>.md` が既に存在すれば何もせず正常終了（ベキ等性）。

### Step 2. 前回結果の読み込み

`reports/latest.json` を読む。`subsidies` の全件が監視対象。前回から日が空いていても `survey_date` を基準に淡々と差分を取る。

### Step 3. 既存案件の状態確認

既存案件のうち、以下に該当するものを優先的にWebSearch/WebFetchで再確認する（全件を毎日深掘りしない）:

- 締切が30日以内のもの（残日数の再計算は全件必ず行う）
- `status` が「公募開始待ち」「結果発表待ち」「未定」系のWatch案件
- 前回 `deadline_note` に「要確認」「未掲載」等の宿題が書かれているもの

確認できた変化（公募開始・締切確定・受付終了・採択発表など）は「更新」として記録。締切超過が確実な案件は「終了」に落とす。

### Step 4. 新規案件の探索

上記「調査の重点」の 地域×カテゴリ でWebSearchし、latest.json にない案件を探す。検索は合計 20〜25 クエリ程度まで。

### Step 5. URL死活確認

掲載する全URLを `curl -s -o /dev/null -w "%{http_code}" -L` で一括確認。200系は `url_verified: true`。リンク切れ（404等）は正しいURLを探し直し、見つからなければその案件をレポートに「URL不明」と明記した上で `url_verified: false`。

### Step 6. latest.json の更新

**スキーマの正は `docs/latest-json.md`。項目名を勝手に変えない**（`scripts/notify_discord.py` が読むため）。

- トップレベル: `survey_date` / `company` / `subsidies` / `notes`
- 各案件: `id`, `name`, `authority`, `region`, `summary`, `amount`, `subsidy_rate`, `deadline` (ISO日付 or null), `deadline_note`, `url`, `url_verified`, `relevance` (高/中/低), `relevance_reason`, `status`, `category`
- **`amount`（補助額）と `subsidy_rate`（補助率）はこの調査の主役**。通知の一番目立つ位置に出るので、必ず公式情報で埋める。
  - `amount` 例: `上限500万円`、`100万〜1,000万円`
  - `subsidy_rate` 例: `2/3以内`、`1/2（小規模事業者は2/3）`、`定額`
  - 公募要領に記載がない・確認できない場合のみ `記載なし` とし、`deadline_note` か `notes` に「補助率要確認」と残して翌日の宿題にする
- `id` は日をまたいで**変えない**（差分検知の軸）
- **新規案件のみ** `new_this_survey: true` を付ける。**前回の new_this_survey は必ず全て外す**（Discord通知の「新規」件数がこのフラグで決まる）
- 終了した案件は `subsidies` から削除（レポート側に「終了」として記録を残す）

### Step 7. レポート保存

`reports/YYYY-MM-DD.md` に以下の構成で保存:

1. ヘッダ（調査日時 / 調査対象地域 / 掲載件数（新規X・更新Y・終了Z）/ URL死活確認の要約）
2. `## 📊 前回（YYYY-MM-DD）からの差分` — 🆕新規 / 🔄更新 / ✅終了 / 📋Watch項目の確認結果 / 📎調査したが掲載を見送った案件
3. `## ⚠️ 終了間近（申請期限2週間以内）` — 期限・残日数・補助金名・関連度・**補助額・補助率**のテーブル
4. `## 🎯 関連度「高」の補助金（優先度順）` — 各案件の詳細（管轄/概要/**補助額・補助率**/期限/URL/理由）
5. 関連度「中」「低」は一覧表でよい

### Step 8. GitHubにpush

リポジトリ直下で:

```sh
git add reports/ && git commit -m "add: YYYY-MM-DD 補助金・助成金調査レポート（N件・X件新規・Y件更新）" && git push
```

push成功でGitHub ActionsがDiscord通知を送る。push失敗はログに残して終了（レポートはローカルに残るので翌日リカバリ可能）。

## エラー時の挙動

- WebSearchが全滅 → `logs/errors.log` に追記して終了（レポートは作らない）
- 一部の検索だけ失敗 → 取れた分でレポート作成、レポート末尾に `（注: <地域/案件>は検索失敗）` と明記
- latest.json が壊れている/読めない → `logs/errors.log` に追記して終了。**勝手に作り直さない**

## 注意

- このプロンプトは `claude -p` 非対話モードから呼ばれる前提
- TodoWrite / TaskCreate は使わない（出力ノイズになる）
- 標準出力は実行サマリー数行のみ
- 編集するのは `reports/` 配下だけ。`.github/` やこのプロンプト自体は触らない
- 毎週回るので1回で完璧を目指さない。宿題は `deadline_note` や Watch項目に「要確認」と書いて翌週に回す
